# Авторизация родителя — дизайн

## Цель

Добавить перед кабинетом родителя полноценную регистрацию и авторизацию через Supabase. Родитель регистрируется один раз, а при последующих запусках сохранённая сессия автоматически восстанавливается и приложение сразу открывает родительский кабинет.

## Границы первой версии

- Авторизация нужна только для режима родителя.
- Детский режим остаётся отдельным и не требует email или пароля.
- Поддерживаются регистрация, вход, выход, восстановление забытого пароля и установка нового пароля после перехода из письма.
- Минимальная длина пароля — 6 символов. Клиентская проверка и настройка Supabase должны использовать одно и то же ограничение.
- Аккаунт родителя создаётся по имени, email и паролю.
- Авторизация реализуется нативно на Android через `supabase-kt`, без WebView.

## Пользовательский сценарий

### Первый запуск родительского режима

1. На стартовой странице пользователь нажимает «Режим родителя».
2. Если активной сессии нет, открывается единая страница авторизации с вкладками «Вход» и «Регистрация».
3. Во вкладке «Регистрация» родитель вводит имя, email, пароль и повтор пароля.
4. После успешной регистрации:
   - при отключённом подтверждении email пользователь сразу попадает в кабинет;
   - при включённом подтверждении email появляется сообщение с просьбой открыть письмо, после подтверждения пользователь возвращается к входу.
5. После успешного входа открывается кабинет родителя.

### Последующие запуски

1. При старте приложение ждёт завершения загрузки сохранённой Supabase-сессии.
2. Если сессия действительна, она автоматически обновляется и родитель сразу попадает в кабинет без повторного ввода пароля.
3. Страница входа появляется снова только после явного выхода, удаления данных приложения либо невозможности обновить отозванную или истёкшую сессию.

### Восстановление пароля

1. На вкладке «Вход» родитель нажимает «Забыли пароль?».
2. Открывается небольшое диалоговое окно с полем email.
3. После отправки всегда показывается нейтральное сообщение: «Если аккаунт с такой почтой существует, мы отправили письмо».
4. Ссылка из письма открывает приложение по deep link и показывает страницу «Новый пароль».
5. Родитель дважды вводит новый пароль длиной не менее 6 символов.
6. После успешного изменения приложение открывает кабинет родителя.

## Визуальный дизайн

Используется утверждённый вариант A — одна страница с двумя вкладками.

- Светлый тёплый фон соответствует текущему приложению.
- Сверху располагаются кнопка «Назад» и портрет помощника родителя.
- Портрет кадрирован по грудь. Бирюзовая рамка имеет среднюю утверждённую толщину и находится позади персонажа; уши выступают над рамкой, линия не проходит поверх ушей.
- Под портретом: заголовок «Кабинет родителя» и подпись «Войди, чтобы управлять делами семьи».
- Переключатель «Вход / Регистрация» выполнен как две вкладки в одной сиреневой панели.
- Вход содержит email, пароль, основную кнопку «Войти» и текстовую кнопку «Забыли пароль?».
- Регистрация содержит имя, email, пароль, повтор пароля и кнопку «Создать аккаунт».
- У поля пароля есть кнопка показать/скрыть пароль.
- Все интерактивные элементы имеют область нажатия минимум 48 dp; содержимое прокручивается и не перекрывается экранной клавиатурой.
- Ошибка показывается рядом с соответствующим полем. Общая серверная ошибка показывается над основной кнопкой.
- Во время запроса основная кнопка заблокирована и содержит индикатор загрузки без изменения своих размеров.

## Проверки формы

- Email обязателен, обрезается по краям и проверяется на базовый корректный формат.
- Пароль обязателен и содержит минимум 6 символов.
- Для регистрации имя обязательно после удаления пробелов по краям.
- При регистрации пароли должны совпадать.
- При установке нового пароля действуют те же требования и повтор пароля.
- Локальные ошибки выводятся до сетевого запроса.
- Пароли, access token и refresh token не записываются в журналы.

## Архитектура

### Состояние авторизации

`AuthViewModel` управляет единым состоянием:

- `Initializing` — чтение сохранённой сессии;
- `Unauthenticated` — показ входа или регистрации;
- `Submitting` — выполняется запрос;
- `AwaitingEmailConfirmation` — регистрация завершена, требуется подтверждение email;
- `PasswordRecoverySent` — письмо восстановления запрошено;
- `PasswordRecovery` — приложение открыто по recovery deep link;
- `Authenticated` — родитель вошёл;
- `Error` хранится как данные текущей формы, а не как отдельный навигационный экран.

### Supabase

- `autoLoadFromStorage` остаётся включённым, чтобы загрузить сессию после перезапуска.
- `alwaysAutoRefresh` остаётся включённым, чтобы автоматически обновлять access token.
- UI реагирует на `sessionStatus`, а не принимает решение только по мгновенному `currentUserOrNull()` до завершения инициализации.
- Репозиторий предоставляет операции регистрации, входа, выхода, отправки recovery-письма и установки нового пароля.
- Для Android настраивается deep link `myway://auth-callback`; этот адрес также добавляется в разрешённые Redirect URLs проекта Supabase.
- `MainActivity` передаёт входящий intent клиенту Supabase, чтобы обработать подтверждение email и восстановление пароля.

### Навигация

- Стартовый выбор режима остаётся первым экраном приложения.
- При выборе родительского режима корневой экран проверяет состояние Supabase-сессии.
- `Authenticated` открывает существующий `ParentModeScreen`.
- Выход из профиля очищает Supabase-сессию и возвращает на страницу авторизации родителя.
- Кнопка «Назад» на странице авторизации возвращает к выбору режима.

## Ошибки и устойчивость

- Ошибки сети не стирают введённые поля, кроме паролей после успешной операции.
- Технические тексты Supabase преобразуются в короткие русские сообщения: неверный email/пароль, аккаунт уже существует, нет сети, слишком много попыток и неизвестная ошибка.
- При восстановлении пароля не раскрывается, зарегистрирован ли указанный email.
- Если сохранённую сессию невозможно обновить, приложение возвращается к входу и показывает понятное сообщение.
- Экран `Initializing` не показывает на мгновение форму входа, чтобы избежать визуального скачка перед автоматическим входом.

## Тестирование и критерии готовности

- Unit-тесты проверяют валидацию email, имени, длины 6 символов и совпадения паролей.
- Unit-тесты `AuthViewModel` проверяют успешную регистрацию, вход, сохранённую сессию, выход, recovery-письмо, установку нового пароля и русские ошибки.
- Compose-тесты проверяют переключение вкладок, состав полей, блокировку кнопки при ошибках и отображение загрузки.
- Deep-link тест проверяет переход на страницу нового пароля.
- Ручная проверка выполняется на эмуляторе и физическом телефоне: регистрация, повторный запуск без входа, выход, неверный пароль и полный recovery-сценарий.
- Существующие детские экраны и дизайн кабинета родителя не изменяются.

## Внешняя настройка

В Supabase Dashboard необходимо:

1. установить минимальную длину пароля 6 символов;
2. добавить `myway://auth-callback` в Redirect URLs;
3. определить, требуется ли подтверждение email;
4. перед публичным выпуском подключить собственный SMTP, потому что тестовая отправка Supabase имеет ограничения.
