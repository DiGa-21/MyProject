# React Native: авторизация родителя — дизайн второго этапа

## Цель

Подключить React Native-клиент в `mobile-react-native` к существующему проекту Supabase и реализовать полноценную авторизацию родителя: регистрацию, вход, восстановление сессии после перезапуска, выход и восстановление пароля. Резервное Kotlin-приложение и существующая схема базы данных не изменяются.

## Границы этапа

В этап входят:

- регистрация родителя по имени, email и паролю;
- вход по email и паролю;
- автоматическое восстановление сохранённой сессии;
- выход из аккаунта;
- восстановление забытого пароля через письмо и deep link;
- временный защищённый кабинет с именем, email и кнопкой выхода;
- русские сообщения об ошибках;
- unit- и UI-тесты, Android-сборка и ручная проверка.

В этап не входят:

- подтверждение email после регистрации;
- перенос полного родительского кабинета, помощника, родительских дел и управления детьми;
- подключение детского устройства по коду;
- изменение таблиц, RLS-политик или RPC Supabase;
- удаление или переписывание Kotlin-версии.

## Принятые продуктовые решения

- Подтверждение email временно отключено для семейной версии. После регистрации родитель сразу получает сессию и попадает в кабинет.
- Минимальная длина пароля — 6 символов.
- Восстановление пароля реализуется уже на втором этапе.
- После входа показывается временный рабочий кабинет: имя, email, сообщение об успешном входе и кнопка «Выйти».
- Полный кабинет переносится отдельным следующим этапом.

## Архитектурный подход

Используется отдельный слой авторизации, а не прямые вызовы Supabase из UI.

- `AuthGateway` описывает операции регистрации, входа, выхода, запроса письма восстановления и установки нового пароля.
- Реализация `SupabaseAuthGateway` инкапсулирует `supabase-js` и преобразует ответы SDK в типы приложения.
- `AuthProvider` владеет состоянием сессии, подписывается на изменения Supabase Auth и предоставляет действия экранам.
- Экраны остаются презентационными: отображают состояние, валидируют ввод через отдельные функции и вызывают действия провайдера.
- В тестах реальный gateway заменяется fake-реализацией.

Redux или Zustand на этом этапе не добавляются: объёма состояния достаточно для React Context и сфокусированного auth reducer/provider.

## Навигация

Маршруты Expo Router:

- `/` — существующий выбор режима;
- `/parent` — точка входа и проверка состояния родительской сессии;
- `/parent/auth` — единая страница с вкладками «Вход» и «Регистрация»;
- `/parent/cabinet` — временный защищённый кабинет;
- `/parent/reset-password` — ввод нового пароля после перехода из письма.

Корневой layout оборачивает маршруты в `AuthProvider`. При открытии родительского режима:

1. приложение ждёт загрузки сохранённой сессии;
2. действующая сессия переводит в `/parent/cabinet`;
3. отсутствие сессии переводит в `/parent/auth`;
4. recovery deep link имеет приоритет и открывает `/parent/reset-password`;
5. выход очищает сессию и возвращает на `/parent/auth`.

Во время инициализации показывается спокойный экран загрузки на тёплом фоне. Форма входа не должна кратко появляться перед автоматическим открытием кабинета.

## Экран входа и регистрации

Сохраняется утверждённый вариант A:

- тёплый светлый фон;
- кнопка «Назад»;
- портрет помощника родителя по грудь;
- уши выступают над бирюзовой рамкой, линия рамки не проходит поверх ушей;
- заголовок «Кабинет родителя»;
- подпись «Войди, чтобы управлять делами семьи»;
- вкладки «Вход / Регистрация» в общей сиреневой панели.

Вкладка «Вход» содержит email, пароль, показать/скрыть пароль, кнопку «Войти» и ссылку «Забыли пароль?».

Вкладка «Регистрация» содержит имя, email, пароль, повтор пароля и кнопку «Создать аккаунт».

Интерактивные элементы имеют область нажатия не меньше 48 dp. Содержимое прокручивается, учитывает safe area и не перекрывается клавиатурой. При сетевой ошибке имя и email сохраняются; пароли очищаются только после успешной операции или по явному решению пользователя.

## Валидация и ошибки

Локально, до запроса к Supabase, проверяются:

- обязательное имя после `trim`;
- базовый формат email после `trim` и приведения к нижнему регистру;
- пароль длиной не менее 6 символов;
- совпадение пароля и его повтора.

Ошибка поля показывается рядом с полем. Общая серверная ошибка показывается над основной кнопкой. Во время запроса основная кнопка заблокирована и показывает индикатор без изменения размеров.

Технические ошибки Supabase преобразуются в короткие русские сообщения для следующих случаев:

- неверный email или пароль;
- аккаунт уже существует;
- отсутствует интернет;
- слишком много попыток;
- сессия истекла или была отозвана;
- неизвестная ошибка.

Пароли, access token, refresh token и ссылки восстановления не выводятся в журналы.

## Регистрация и профиль

React Native использует тот же Supabase-проект, что и Kotlin-приложение. При `signUp` имя передаётся в metadata как `display_name`.

Существующий серверный триггер `handle_new_user` создаёт или обновляет строку `public.profiles`, поэтому новые аккаунты совместимы с обеими версиями клиента. Новая миграция базы данных для этого этапа не нужна.

Подтверждение email отключается в Supabase Dashboard. Клиент всё равно обрабатывает неожиданный ответ без сессии понятным сообщением, чтобы не зависнуть при ошибочной серверной настройке.

## Хранение сессии и конфигурация

Используется `@supabase/supabase-js` с React Native storage-адаптером, `persistSession: true`, `autoRefreshToken: true` и `detectSessionInUrl: false`. Автоматическое обновление токена активно, пока приложение находится на переднем плане.

Конфигурация читается из:

- `EXPO_PUBLIC_SUPABASE_URL`;
- `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.

Локальный `.env` уже исключён из Git. В репозиторий добавляется только `.env.example` с пустыми значениями. Service role key и другие серверные секреты в мобильный клиент не добавляются.

При временной потере сети действующая локальная сессия не удаляется. Явный выход очищает сессию. Если сохранённая сессия отозвана и не обновляется, приложение возвращает пользователя на вход с понятным сообщением.

## Восстановление пароля и deep link

Сценарий:

1. родитель нажимает «Забыли пароль?»;
2. вводит email;
3. приложение вызывает отправку recovery-письма с redirect URL `myway://reset-password`;
4. всегда показывается нейтральное сообщение «Если аккаунт с такой почтой существует, мы отправили письмо»;
5. ссылка из письма открывает приложение на `/parent/reset-password`;
6. родитель дважды вводит новый пароль длиной не менее 6 символов;
7. после успешного изменения открывается временный кабинет.

В `app.json` задаётся схема `myway`. В Supabase Dashboard адрес `myway://reset-password` добавляется в разрешённые Redirect URLs. Ссылка не должна вести на `localhost`.

## Временный кабинет

Защищённый экран показывает:

- заголовок «Мой кабинет»;
- имя из `public.profiles.display_name` с безопасным fallback на metadata пользователя;
- email текущего пользователя;
- сообщение «Ты вошла в аккаунт»;
- кнопку «Выйти».

Экран не переносит остальные функции старого кабинета и явно остаётся промежуточным состоянием второго этапа.

## Тестирование

Unit-тесты проверяют:

- валидацию имени, email, длины пароля и совпадения паролей;
- преобразование ошибок в русские сообщения;
- переходы auth reducer/provider между initializing, unauthenticated, submitting, authenticated и recovery;
- регистрацию, вход, выход и восстановление с fake gateway.

UI-тесты React Native Testing Library проверяют:

- переключение вкладок;
- состав полей и доступность элементов;
- блокировку кнопок при ошибках и во время запроса;
- переход в кабинет при действующей сессии;
- запрет кабинета без сессии;
- форму нового пароля.

Ручная проверка на эмуляторе:

1. регистрация без подтверждения email;
2. немедленное открытие кабинета;
3. повторный запуск без нового входа;
4. выход и повторный вход;
5. неверный пароль и отсутствие сети;
6. recovery-письмо, deep link и новый пароль.

После автоматических проверок собирается Android debug APK. При доступном телефоне основной сценарий повторяется на физическом устройстве.

## Критерии готовности

- Родитель регистрируется и входит через существующий Supabase-проект.
- После регистрации без email-подтверждения сразу открывается кабинет.
- Сессия восстанавливается после полного перезапуска приложения.
- Выход возвращает на страницу авторизации.
- Невозможно открыть кабинет без действующей сессии.
- Recovery-ссылка открывает приложение, а не `localhost`.
- Новый пароль принимается и позволяет повторный вход.
- Все сообщения интерфейса для пользователя написаны по-русски.
- `.env` и секреты отсутствуют в Git.
- Тесты, typecheck, lint и Android-сборка проходят.
- Kotlin-приложение и существующая схема Supabase не изменены.
