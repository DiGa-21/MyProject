# React Native: первый этап переноса

## 1. Цель

Создать рядом с действующим Kotlin/Jetpack Compose-приложением отдельный кроссплатформенный каркас на React Native. Первый этап должен запускаться на Android, повторять стартовый экран «Мой путь» и обеспечивать рабочие переходы в режим ребёнка и режим родителя.

## 2. Границы этапа

В первый этап входят:

- отдельный проект `mobile-react-native` в корне репозитория;
- Expo SDK 57, React Native, TypeScript и Expo Router;
- стартовый экран с логотипом и выбором режима;
- временный экран режима ребёнка;
- временный экран режима родителя;
- работа кнопки возврата внутри интерфейса и системной кнопки Android;
- адаптация к системным панелям и разным размерам Android-экранов;
- автоматические проверки и запуск на Android-эмуляторе.

В первый этап не входят:

- регистрация, вход и восстановление пароля;
- подключение ребёнка по коду;
- чтение или запись данных Supabase;
- локальная база данных;
- кабинеты, дела, комната, награды, игра и раздел «Попробуй»;
- сборка и проверка iOS.

Эти возможности переносятся отдельными последующими этапами.

## 3. Сохранение действующего приложения

Существующее Android-приложение остаётся резервной рабочей версией. Папки `app`, `supabase`, `docs`, существующие Gradle-файлы и Kotlin-код не переносятся и не удаляются.

Новый клиент располагается по пути:

```text
mobile-react-native/
```

Он имеет собственные зависимости, конфигурацию сборки и исходный код. Общей частью на следующих этапах станет удалённая схема Supabase, но на первом этапе новый клиент к ней не подключается.

## 4. Технологии и структура

- Expo SDK 57;
- React Native;
- TypeScript со строгой проверкой типов;
- Expo Router для файловой навигации;
- React Native Safe Area Context для учёта системных областей;
- тестовый стек, совместимый с шаблоном Expo и React Native Testing Library.

Минимальная структура маршрутов:

```text
mobile-react-native/
├── app/
│   ├── _layout.tsx
│   ├── index.tsx
│   ├── child.tsx
│   └── parent.tsx
├── src/
│   ├── components/
│   └── theme/
└── assets/
    └── images/
```

`index.tsx` отвечает только за стартовый экран. `child.tsx` и `parent.tsx` являются временными экранами-заглушками следующего этапа. Повторяющиеся визуальные элементы выносятся в небольшие компоненты, а цвета, размеры и интервалы — в тему.

## 5. Стартовый экран

Экран повторяет характер действующего приложения:

- светлый кремовый фон;
- существующий логотип «Мой путь»;
- заголовок «Мои домашние дела»;
- карточка «Режим ребёнка»;
- карточка «Режим родителя»;
- подпись версии в нижней части экрана.

Логотип копируется из существующего ресурса `app/src/main/res/drawable-nodpi/app_logo.png` в каталог ресурсов React Native. Исходный файл Kotlin-приложения не изменяется.

Карточки являются полноценными доступными кнопками. Минимальная удобная область нажатия — 48×48 логических пикселей. Элементы имеют русские подписи и стабильные тестовые идентификаторы.

Экран учитывает верхнюю и нижнюю системные области Android. Контент не должен перекрываться строкой состояния, жестовой полосой или системной панелью навигации. Разметка должна сохранять читаемость на Pixel 6 и Redmi пользователя без фиксированной привязки к одной высоте экрана.

## 6. Навигация

Поток первого этапа:

```text
Стартовый экран
├── Режим ребёнка → временный экран ребёнка
└── Режим родителя → временный экран родителя
```

Временный экран ребёнка содержит:

- заголовок «Режим ребёнка»;
- сообщение «Подключение по коду появится на следующем этапе»;
- кнопку «Назад».

Временный экран родителя содержит:

- заголовок «Режим родителя»;
- сообщение «Регистрация и вход появятся на следующем этапе»;
- кнопку «Назад».

Возврат работает как по кнопке в интерфейсе, так и по системной кнопке Android.

## 7. Данные и безопасность

Первый этап не использует пользовательские данные и не выполняет сетевые запросы. Существующие записи Supabase не изменяются.

В `.gitignore` нового проекта включаются:

- `.env`;
- `.env.local` и остальные локальные варианты `.env`;
- `node_modules`;
- локальное состояние Expo;
- локальные Android-настройки;
- ключи подписи и файлы хранилищ ключей.

Секреты Supabase не копируются из `local.properties` в новый клиент на этом этапе.

## 8. Обработка ошибок

Так как сетевого слоя нет, пользовательские ошибки первого этапа ограничены навигацией и отображением ресурсов. Отсутствующий ресурс должен выявляться во время сборки. Неизвестный маршрут обрабатывается стандартным механизмом Expo Router без аварийного завершения приложения.

Если на компьютере отсутствует Node.js нужной версии или Android-инструмент, настройка останавливается с диагностикой. Ошибка нового клиента не должна затрагивать сборку резервного Kotlin-приложения.

## 9. Проверка

Обязательные проверки:

1. TypeScript завершается без ошибок.
2. Стартовый экран показывает логотип, заголовок и обе кнопки режима.
3. Кнопка ребёнка открывает временный экран ребёнка.
4. Кнопка родителя открывает временный экран родителя.
5. Кнопка «Назад» и системный возврат приводят на стартовый экран.
6. Android-сборка завершается успешно.
7. Экран визуально проверен на Android-эмуляторе; контент не перекрыт системными панелями.

Установка на физический Android-телефон возможна после успешной проверки на эмуляторе, но не является обязательным условием завершения первого этапа.

## 10. Критерии готовности

Этап считается завершённым, когда:

- новый клиент расположен в `mobile-react-native`;
- резервная Kotlin-версия продолжает собираться без изменений;
- стартовый экран визуально соответствует текущему стилю «Мой путь»;
- оба перехода и возврат работают;
- проверки типов, тесты и Android-сборка проходят;
- никакие пользовательские данные и секреты не добавлены в Git.
